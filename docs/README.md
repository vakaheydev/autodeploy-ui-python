# Документация публичного ядра

Эта папка разделена по владельцу знаний. Такое разделение обязательно: публичный
агент не должен придумывать корпоративную реализацию, а корпоративный агент —
копировать или патчить внутренности ядра вместо использования extension points.

## Публичное ядро

Читайте только необходимые документы:

| Задача | Документ | Источник истины в коде |
|---|---|---|
| Form API, server-side lifecycle, React boundary | [WEB_ARCHITECTURE.md](WEB_ARCHITECTURE.md) | `webapp/form_runtime.py`, `forms/` |
| Copilot, helper sessions, drafts, trust model | [AI_AGENT_ARCHITECTURE.md](AI_AGENT_ARCHITECTURE.md) | `opencode_integration/`, `webapp/ai_routes.py` |
| MCP transport, инструменты и ограничения | [MCP.md](MCP.md) | `webapp/mcp_server.py` |
| Установка, release archive и launcher | [INSTALLATION.md](INSTALLATION.md) | `launcher/`, `scripts/build_release.py` |

Корневой [AGENTS.md](../AGENTS.md) — обязательная инструкция для AI-агента,
который меняет публичный репозиторий.

## Корпоративная реализация

Вся корпоративная документация изолирована в [corp/](corp/README.md). Папка
самодостаточна: её можно скопировать в private repository без остальных
документов публичного ядра. Там зафиксировано текущее целевое состояние, а не
история миграции с Tkinter-монолита.

При изменении публичного extension contract необходимо в том же pull request
обновить соответствующий документ в `docs/corp/`.

## Правила документации

- Описывайте только поведение, существующее в текущем коде.
- Для контрактов приводите точную сигнатуру, точку подключения и ожидаемые
  ошибки; не пересказывайте реализацию неформально.
- Секреты, реальные URL, заявки, идентификаторы и payload из корпоративной среды
  не должны попадать в примеры.
- Не добавляйте промежуточные инструкции вида «скопируйте старый файл и временно
  поправьте его». Документируйте конечную структуру пакетов и поддерживаемый API.
- Если код и Markdown расходятся, код и тесты являются источником истины, а
  документацию нужно исправить в той же задаче.

## Проверка локальных ссылок

После изменения Markdown выполните из корня репозитория:

```bash
python scripts/check_docs.py
git diff --check
```

`scripts/check_docs.py` проверяет относительные ссылки и запрещённые ссылки на
удалённые migration-документы. Внешние URL он намеренно не запрашивает.
